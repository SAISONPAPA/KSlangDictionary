# HelloKSlang — K-Pop & K-Drama Slang Dictionary

A slang dictionary for international (English/Spanish-speaking) K-pop and K-drama fans, aged roughly 10–30. Look up a word, hear it pronounced, browse by category, or see what's newly trending.

**Live status:** Not yet deployed. See "Deploy to GitHub Pages" below.

## 📁 What's in this repo

| File | What it is |
|---|---|
| `index.html` | Homepage — search only (Chrome/Google-style minimal landing) |

| `data/kslang-slang-database.xlsx` | The master word list (650 terms) — **source of truth**. Auto-regenerated by GitHub Actions whenever `scripts/build_kslang_db.py` changes (see "Automated rebuilds" below). |

| `scripts/generate_word_pages.py` | Regenerates all 650 files in `word/` from that same master word list. |

Each HTML file is **fully self-contained** — all CSS and JS (including the entire word database) is inlined in the file itself. No build step, no server, no dependencies. You can open any of these files directly in a browser and they work.

## 🚀 Deploy to GitHub Pages

1. Push this repo's contents to a GitHub repository (root of `main` branch is simplest — no `/docs` folder needed).
2. In the repo: **Settings → Pages → Source** → select `main` branch, `/ (root)` folder → Save.
3. GitHub gives you a live URL like `https://yourusername.github.io/reponame/index.html`.
4. **(Optional) Custom domain:** In the same Pages settings, enter your domain (e.g. `kslangdictionary.com`). This creates a `CNAME` file in the repo automatically. Then at your domain registrar, add:
   - 4 **A records** for the root domain pointing to: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - 1 **CNAME record** for `www` pointing to `yourusername.github.io`
   - Once DNS propagates (can take a few hours), enable **"Enforce HTTPS"** in Pages settings.

## 🤖 Automated rebuilds (GitHub Actions)

As of now, adding words no longer requires manually re-running scripts and re-uploading hundreds of files. **Just edit `scripts/build_kslang_db.py` and push to `main`** — a GitHub Actions workflow (`.github/workflows/rebuild.yml`) automatically:

1. Runs `scripts/safety_check.py` — scans every word for a small list of red-flag keywords (sexual/explicit content). **If anything is flagged, the whole workflow fails and nothing gets published.**
2. Regenerates `data/kslang-slang-database.xlsx`
3. Regenerates all `word/*.html` pages
4. Regenerates the embedded `SLANG_DB` inside `index.html`, `category.html`, `trending.html`, `submit.html`
5. Regenerates `whatsnew.html` from `NEW_WORDS_LOG` (see below)
6. Regenerates `sitemap.xml` so Google always sees the current full page list (see "Google Search Console" below)
7. Commits and pushes the result back to `main` automatically

**⚠️ One-time setup required on GitHub before this works:** go to your repo's **Settings → Actions → General → Workflow permissions**, and select **"Read and write permissions"** (it defaults to read-only, which would make the final `git push` step fail with a permissions error).

**What this does NOT automate:** finding new slang and deciding it's safe/appropriate to add is still a human (or Claude, prompted by a human) judgment call — the safety check is a keyword-based last-resort net, not a substitute for that. You still write the new word entries into `build_kslang_db.py` yourself; only the "regenerate + republish everything" grunt work is automated.

**Manually triggering a rebuild** (e.g. to force-refresh without changing the word list): go to the repo's **Actions** tab → **"Rebuild site data"** workflow → **"Run workflow"** button.

These exist purely for **Google search traffic**. Someone searching "daebak meaning" or "jonbeo 뜻" can land directly on `word/dae-bak.html` or `word/jon-beo.html` instead of needing to already know about HelloKSlang and use its search bar. Each page:

- Is much lighter than the main 4 pages (~15KB vs ~300KB) since it only needs its own word's data, not all 650

**✅ Domain set:** all canonical URLs point to `https://hellokslang.com`. If the domain ever changes again, there's one constant to edit — `SITE_URL` near the top of `scripts/generate_word_pages.py` — then re-run the script to regenerate all 650 pages with the new domain.

**To regenerate these pages** (after editing the word list in `scripts/build_kslang_db.py`):
```bash
cd scripts
python3 build_kslang_db.py        # rebuilds data/kslang-slang-database.xlsx
python3 generate_word_pages.py    # rebuilds all word/*.html from the same data
```
Both scripts need `openpyxl` installed (`pip install openpyxl`).

## 🆕 The "What's New" page — how to keep it updated

`whatsnew.html` reads from `NEW_WORDS_LOG` near the top of `scripts/build_kslang_db.py`. It's a simple list — **every time you add new words, also add one line here**:

```python
NEW_WORDS_LOG = [
    ("2026-07-29", ["영크크"]),
    ("2026-08-05", ["새단어1", "새단어2"]),   # <- add new entries like this, newest at top
]
```

Words added *before* this log existed (the original 650) aren't shown on the page — there's no real historical date to put them under, and backdating them would be inaccurate. The page only tracks words added going forward.

This regenerates automatically as part of the GitHub Actions rebuild whenever `build_kslang_db.py` changes — no separate manual step needed as long as you remember to add the log line.

## 📖 How word data works (read this before adding words)

There is **no live database and no backend**. The 650-word dictionary is a plain JavaScript array (`SLANG_DB`) that's copy-pasted into all four main HTML files identically, plus rendered individually into each `word/*.html` page.

- Searching, category browsing, and pronunciation all run **entirely in the visitor's browser**.
- Anyone can view the full word list via "View Page Source" — there's no scraping protection.
- **To add a word: edit `scripts/build_kslang_db.py` and push to `main`.** GitHub Actions handles regenerating the xlsx, all 650+ word pages, and the embedded array in the 4 main pages automatically — see "Automated rebuilds" above. You no longer need to manually copy anything between files.
